# ZEUS 3.21 and SADIE 3.5 tapes

This directory keeps the recovered tape sources, the SIMH tape images used by
MAME, and reproducible extracted contents separate:

```
originals/   Original recovery inputs
images/      Generated SIMH `.tap` images
extracted/   Files generated by decoding the `.tap` images
```

## Build the tape images

From the repository root:

```sh
python3 tapes/build_tape_images.py
```

The install builder checks every recovered TCC block CRC.  The only damaged
block is install tape file 8, block 169.  It reconstructs that block using the
independently recovered files in `originals/install-3.21/S8000-2.tar`, while
regenerating the UNIX dump headers and checksums.  The upgrade source is already
a tar stream and is divided into 10,240-byte tape records.

The SADIE cartridge was recovered as three independent tracks. The builder
checks the CRC of every captured record and creates one SIMH TAP image per
track, preserving the separate logical BOT and file numbering used by TCC mode
1. All records in the current three source archives pass their CRC checks.

The source archives are the current objects linked as SADIE Track 0, Track 1
and Track 2 in the
[VCFed recovery thread](https://forum.vcfed.org/index.php?threads/zilog-system-8000-model-21.1255068/page-4).

## Extract the tape images

```sh
python3 tapes/extract_tape_images.py
```

This reads only the generated `.tap` images. It writes each logical tape file,
extracts the UNIX dump and tar archives, and writes the SADIE logical binaries
under `tapes/extracted/sadie-3.5/track-N/logical/`. Existing generated
extraction directories are replaced, so the result cannot retain files from an
older run.
